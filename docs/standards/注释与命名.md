# 注释与命名

**状态：草稿（待评审）**
**读者：** 所有写 Java 代码的人与 AI 协作代理
**基准：** `features/channel`。本文所有"应该怎么写"都指向 channel 的真实代码；出现分歧时以 channel 为准并回头改规范。

---

## 1. 注释的分工

| 信息类型 | 写在哪 | 例子 |
|---|---|---|
| 局部约束、边界、失败语义、副作用 | 类/方法注释 | `RealtimeEventPublisher`：先落窗口再广播 |
| 跨模块规则、结构、依赖方向 | `docs/` | 模块依赖矩阵 |
| "代码在做什么" | 不写。代码自己表达 | `i++` 不写 `// 自增` |

判断标准：**注释只回答"代码无法自证的部分"**——为什么这样、边界在哪、失败会怎样、调用顺序有什么要求。凡是读签名就能知道的，不写。

## 2. 类级注释

### 2.1 必须有的两类（所有类）

```java
/**
 * 频道投影。
 * 职责：向协议层暴露频道列表与详情所需的稳定字段。
 * 边界：只承载频道聚合自身的字段，不承载成员关系、禁言记录与申请记录；不承载协议包装逻辑。
 */
```

- `职责`：一句话说清"这个类为谁、解决什么"。
- `边界`：明确"不做什么"，这是本仓库最有价值的一行注释——它阻止下一个人把职责塞进来。

### 2.2 `domain/api` 接口：加四行

`domain/api` 是跨 feature 的唯一入口，注释必须让调用方不读实现就能正确使用：

```java
/**
 * 频道核心领域 API。
 * 职责：暴露频道列表与详情读取、频道创建、删除与资料更新能力。
 * 边界：不暴露 controller 协议、具体实现类与仓储细节；不负责成员治理、禁言与入群申请。
 * 输入：频道创建、删除与资料更新命令，以及账号与频道标识。
 * 输出：频道投影或频道投影列表。
 * 失败语义：频道不存在抛资源不存在；权限不足抛权限不足；资料非法抛参数错误；存在依赖数据时抛冲突。
 * 调用方：channel controller 与其它 feature 通过本接口操作频道，不直接依赖具体实现类。
 */
```

四行的语义：

| 行 | 必须回答 |
|---|---|
| `输入` | 参数的业务含义与前提（谁的身份、要什么） |
| `输出` | 返回值形态与空值语义 |
| `失败语义` | 失败条件 → 哪类错误码（不写具体 code 值） |
| `调用方` | 谁能调；并声明"不得直接依赖实现类" |

### 2.3 有额外约束的类：按需加行

| 行 | 什么时候写 | 例子 |
|---|---|---|
| `顺序约束` | 调用顺序错会出错 | `RealtimeEventPublisher`：必须先落续传窗口再广播 |
| `容量语义` | 有上限/淘汰策略 | `resume/RealtimeEventLog`：账号数满时只回收已全部过期的账号 |
| `不变量` | 多线程或状态机约束 | `RealtimeConnectionIndex`：Netty 帧不可跨通道共享 |

### 2.4 `record` / 枚举

- 每个分量一个 `@param`，并标注可空与缺失语义：`@param brief 频道简介；可能为空字符串`。
- 时间字段标注单位：`@param serverTime 服务端时间，epoch 毫秒`。
- 枚举每个码值一行注释，写"业务含义"而不是重复名字。

### 2.5 配置记录

```java
/**
 * 数据库服务配置。
 * 职责：控制 database-impl 是否装配。
 * 边界：配置类属于具体数据库实现模块，不进入 infrastructure-basic 或 chat-domain。
 *
 * @param enabled 是否启用数据库服务实现
 */
```

配置类必须写 `边界`，说明"它为什么在这一层"。

## 3. 方法级注释

### 3.1 必写范围

| 位置 | 必写 |
|---|---|
| `domain/api` 接口方法 | ✅ |
| `domain/service` 公开方法 | ✅ |
| `adaptor` / `controller` 的公开入口 | ✅ |
| 基建的公开入口（`TransactionRunner`、`RealtimeFrameCodec`…） | ✅ |
| `record` 的 accessor、简单 getter | ❌ |
| 私有方法 | 仅当含非显然算法、协议细节或易错顺序时 |

### 3.2 结构

一行职责 →（按需）约束/输入/输出/失败语义/副作用 → `@param` / `@return`：

```java
/**
 * 创建普通频道并把创建者设为所有者。
 * 输入：命令携带创建者账号与频道名称、简介、头像。
 * 输出：创建完成后的频道投影。
 * 副作用：写入频道记录与创建者的 OWNER 成员关系，并在事务提交后通知该账号刷新频道集合。
 * 约束：创建的始终是普通频道；系统频道不通过本接口产生。
 */
```

要点：

- `@return` 必须写空值/空列表语义：`@param lastEventId 客户端最后确认的事件 ID` / `@return 后续事件；无新事件时为空列表；锚点已不可用时返回 null`。
- 抛异常的方法写 `失败语义`，不要写 `@throws` 逐个罗列（码表在 `domain/problem`）。
- 有外部副作用（写库、发消息、定时任务、关闭连接）必须写 `副作用`。
- 布尔方法写"什么条件下为 true"，不写"返回是否 xxx"。

### 3.3 禁止

- 复述签名的废话注释（`/** 获取名称 */ public String name()`）。
- 注释掉的代码（用 git 历史，不用注释）。
- 无负责人的 `// TODO`；确需保留时写 `// TODO(<issue 或人>): 原因 + 触发条件`。
- 与实现不一致的注释。改行为必须同一提交内改注释。

## 4. 字段与常量注释

必须注释的：

| 场景 | 例子 |
|---|---|
| 协议字面量 | `/** 事件下发帧的帧类型。 */ public static final String EVENT_FRAME_TYPE = "event";` |
| 阈值 / 容量 / 超时 | 空闲超时、单帧上限、窗口保留时间 |
| 有隐含单位的数值 | `@param serverTime ... epoch 毫秒` |
| 跨类共享的魔数 | 统一抽常量并注释 |

## 5. 测试注释

测试类与方法同样要求注释，但细则归 `docs/standards/测试规范.md`（本轮不重写）。此处只固定两条与本文相关的约定：

- 测试类名 `*Tests`；测试方法名 `methodName_condition_expected()`。
- 每个测试方法的注释写"验证的是哪条契约"，不是复述断言。

## 6. 命名规范

### 6.1 包名

- 全小写，用职责名：`domain/api/channel/input`、`config/ws/resume`。
- 业务 feature 内**禁止**新建 `common`、`util`、`manager`、`helper`、`misc`。
- 基建内已有的 `IdUtil`、`JsonUtil` 保持不动，但不再新增 `*Util`。

### 6.2 类名后缀

| 后缀 | 含义 | 例子 |
|---|---|---|
| `*Api` | `domain/api` 下的对外契约 | `ChannelApi`、`ChannelMemberApi` |
| `*DomainApi` | `domain/service` 下契约的唯一实现 | `ChannelDomainApi` |
| `*Command` / `*Query` | `api/<cap>/input` 下的入参 | `CreateChannelCommand`、`DiscoverChannelsQuery` |
| `*Result` | `api/<cap>/result` 下的出参投影 | `ChannelResult`、`ChannelMemberResult` |
| `*Repository` | `domain/repository` 抽象 | `ChannelRepository` |
| `*Repository`（实现） | `adaptor/persistence`，前缀描述来源 | `DatabaseBackedChannelRepository` |
| `*Query` / `*Notifier` | `domain/capability` 抽象 | `MemberProfileQuery`、`ChannelEventNotifier` |
| 实现类 | `adaptor` 下，前缀描述来源 | `ApiMemberProfileQuery`、`RealtimeChannelEventNotifier` |
| `*Controller` | `controller/http` | `ChannelController`、`ChannelBansController` |
| `*Request` / `*Response` | `controller/http/**/dto` | `CreateChannelRequest`、`ChannelListResponse` |
| `*Properties` | 配置绑定记录 | `RealtimeServerProperties` |
| `*Configuration` | feature 局部装配（仅在必要时） | `AuthConfiguration` |
| `*AutoConfiguration` | `*-impl` 中装配第三方类型的条件自动配置 | `StorageServiceAutoConfiguration` |
| `*Problem` | `domain/problem` 错误码表 | `ChannelProblem` |
| `*Handler` / `*Codec` / `*Publisher` / `*Coordinator` | 协议机制类 | `RealtimeChannelHandler`、`RealtimeFrameCodec` |
| `*Checker` | 启动检查实现 | `DatabaseInitializationChecker` |

命名要能看出**来源与角色**：`DatabaseBacked*` 表示数据来自数据库，`Api*` 表示数据来自其它 feature 的 API。不要用 `Default*`、`Impl*`、`*Manager`。

### 6.3 方法名

| 语义 | 前缀 | 例子 |
|---|---|---|
| 查询单个 | `get` / `find` | `getChannelById`、`findProfiles` |
| 查询列表 | `list` / `find…s` | `listChannels` |
| 判断 | `is` / `has` / `can` | `isAuthenticated`、`hasText` |
| 转换 | `from` / `to` | `ChannelResult.from(channel)` |
| 写入 | `create` / `update` / `delete` / `append` | `createChannel`、`appendMessageRecallAudit` |
| 状态变更 | 动词过去式语义的方法名 | `recall`、`promote`、`ban` |
| 校验 | `require` / `validate` | `requireNonBlank`、`validate` |

命名一致性要求：同一**语义**在同一 feature 内必须用同一个动词；`get` 与 `find` 的区别固定为"必存在（失败抛异常）"与"可空返回"。

### 6.4 常量与变量

- 常量 `UPPER_SNAKE_CASE`；协议字面量、错误原因、事件名必须常量化，不散落字符串。
- 变量名不用单字母（循环下标除外）、不用拼音、不用无意义后缀（`data`、`info`、`obj`、`temp`）。

### 6.5 测试命名

- 类：被测对象 + `Tests`，如 `RealtimeEventLogTests`。
- 方法：`动词_条件_期望`，如 `publish_oversizedEvent_dropsWithoutWindowOrBroadcast`、`validate_blankType_throwsProtocolException`。
