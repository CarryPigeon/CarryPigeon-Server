# 数据库部署

**状态：草稿（待评审）**

**边界：** 本文只说明 MySQL 一侧的准备、初始化与验收。表结构定义见 `docs/sql/`，容器运行见 `operations/Docker与外部服务.md`。

---

## 1. 适用范围

| 项 | 要求 |
|---|---|
| 数据库 | MySQL 8.x（本地 compose 使用 `mysql:8.4`） |
| 字符集 | `utf8mb4`，排序规则 `utf8mb4_unicode_ci` |
| 时区 | 服务端 `+08:00`；连接串 `serverTimezone=Asia/Shanghai` |
| 引擎 | InnoDB（默认） |
| 迁移框架 | **无**。项目没有 Flyway/Liquibase，建表与变更全部靠 `docs/sql/` 手工执行 |

---

## 2. 建库与字符集

```sql
CREATE DATABASE IF NOT EXISTS carrypigeon
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

- 本地 compose 会按 `MYSQL_DATABASE`（默认 `carrypigeon`）自动建库，**但不会建表**。
- 已存在的库请核对字符集：

```sql
SELECT DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA
WHERE SCHEMA_NAME = 'carrypigeon';
```

要求两列分别为 `utf8mb4` / `utf8mb4_unicode_ci`。若为 `utf8`（即 `utf8mb3`），中文 4 字节字符（emoji 等）会写入失败，必须重建或转换后再上线。

---

## 3. 账号与权限

| 账号 | 用途 | 权限 |
|---|---|---|
| 部署/DBA 账号 | 执行 `docs/sql` 下的建表与变更脚本 | 目标库 `DDL` + `DML` |
| 应用账号 | 应用运行时连接（`spring.datasource.username`） | 目标库 `SELECT, INSERT, UPDATE, DELETE`；插件迁移需要 `CREATE, ALTER` |

本项目不要求全局权限，不给应用账号 `DROP DATABASE` 或跨库权限。

## 4. 应用侧连接配置

`application-starter/src/main/resources/application.yaml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/carrypigeon?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&connectTimeout=5000&socketTimeout=30000
    username: carrypigeon
    password: carrypigeon123
    driver-class-name: com.mysql.cj.jdbc.Driver
    hikari:
      connection-timeout: 10000
      validation-timeout: 5000
```

| 参数 | 含义 | 调整场景 |
|---|---|---|
| `useUnicode` + `characterEncoding=utf8` | 连接级字符集协商（配合库的 `utf8mb4`） | 不单独修改 |
| `serverTimezone` | 驱动侧会话时区 | 必须与库/容器时区一致，否则时间字段偏移 |
| `connectTimeout` | 建链超时（毫秒） | 跨机房时适度放宽 |
| `socketTimeout` | 单次读写超时（毫秒） | 大结果集查询报超时时放宽 |
| `hikari.connection-timeout` | 从池中取连接的等待上限（毫秒） | 高并发下告警时评估 |
| `hikari.validation-timeout` | 连接有效性检查上限（毫秒） | 不单独修改 |

数据库实现由开关 `cp.infrastructure.service.database.enabled`（默认 `true`）控制；关闭后 `database-impl` 不装配，应用启动不需要数据库，但所有依赖仓储的功能不可用。

生产环境必须覆盖 `url/username/password`，不得沿用本地默认值。

## 5. 空库初始化流程

脚本位于 `docs/sql/`，**按域拆分、按序执行**：

| 顺序 | 脚本 | 内容 |
|---|---|---|
| 1 | `01-auth.sql` | 认证账号与 refresh session |
| 2 | `02-user.sql` | 用户资料 |
| 3 | `03-channel.sql` | 频道、成员、入会申请、禁言、审计、已读；含唯一 `system` 频道种子 |
| 4 | `04-message.sql` | 消息、mention |
| 5 | `06-plugin.sql` | 插件迁移历史表 `plugin_schema_history` |
| 6（可选） | `90-dev-seed.sql` | 本地联调种子数据（含测试账号），仅限开发环境 |

执行示例：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/01-auth.sql
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/02-user.sql
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/03-channel.sql
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/04-message.sql
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/06-plugin.sql
```

约定：

- 每个脚本内使用 `CREATE TABLE IF NOT EXISTS`，可重复执行；**不提供** `00-all-in-one` 拼接件（避免同一事实两份来源）。
- 脚本之间不强制外键依赖，但执行顺序决定了表与种子数据的可见性，不要打乱。
- `03-channel.sql` 必须保证 `system` 频道唯一；当前仍依赖脚本保证，尚无数据库级唯一约束。

## 6. 重置已污染的环境

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < docs/sql/99-reset.sql
```

- `99-reset.sql` 删除本项目管理的**全部表与数据**，但**不执行 `DROP DATABASE`**。
- 执行后按 §5 重新初始化。
- 生产环境禁止使用；需要保留历史数据的库应走 §9 的备份 + 增量变更，而不是重置。

## 7. 初始化后自检

```sql
-- 表数量与清单
SELECT TABLE_NAME FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'carrypigeon' ORDER BY TABLE_NAME;

-- 字符集与排序规则（全部应为 utf8mb4 / utf8mb4_unicode_ci）
SELECT TABLE_NAME, TABLE_COLLATION FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'carrypigeon';

-- 系统频道必须恰好一条
SELECT id, type FROM channel WHERE type = 'system';
```

验收标准：

1. 表清单与 `docs/sql` 中的定义一致，无残留旧表。
2. 所有表 `TABLE_COLLATION = utf8mb4_unicode_ci`。
3. `system` 频道恰好一条。
4. 应用启动后 `/api/server` 可返回服务发现文档（说明数据库与仓储链路可用）。

---

## 8. 启动期检查的边界（重要）

应用启动时会执行数据库健康检查，但它**只验证连通性**：

```text
DatabaseInitializationChecker（startup）
  → DatabaseHealthService.check()
    → JdbcDatabaseHealthService：执行 SELECT 1
```

因此：

- 数据库连不上 → 启动检查失败，应用按启动检查策略中止或告警（取决于配置）。
- **表不存在、字段缺失、字符集不对 → 启动期不报错**，第一次真实读写才失败。
- 结论：初始化脚本必须在首次启动前执行完成；升级时也必须先改库再发版。

## 9. 备份与恢复

```bash
# 备份（结构 + 数据）
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers \
  carrypigeon > carrypigeon-$(date +%Y%m%d-%H%M).sql

# 恢复
mysql -h 127.0.0.1 -P 3306 -u root -p carrypigeon < carrypigeon-20260101-0300.sql
```

要求：

- 变更表结构前必须备份，且备份文件与脚本版本一起归档。
- `--single-transaction` 只对 InnoDB 生效，本项目全部使用 InnoDB。
- 恢复后按 §7 重新自检。

## 10. 常见故障

| 报错 | 原因 | 处理 |
|---|---|---|
| `1045 Access denied` | 账号/密码错，或账号不存在 | 核对 `spring.datasource.username/password` 与 §3 权限 |
| `1049 Unknown database` | 库未创建 | 执行 §2 |
| `1050 Table already exists` | 重复执行建表语句且未用 `IF NOT EXISTS` | 用 `docs/sql` 现行脚本；或用 §6 重置 |
| `2003 Can't connect` | MySQL 未启动 / 端口未映射 | 见 `operations/Docker与外部服务.md` §8 |
| `Incorrect string value` | 库或表不是 `utf8mb4` | 按 §2 核对并转换 |
| 时间字段偏移 8 小时 | `serverTimezone` 与库时区不一致 | 统一 `Asia/Shanghai` / `+08:00` |
| 启动正常但接口 500（表不存在） | 未执行初始化脚本 | 执行 §5，再重启应用 |
| 插件启动报迁移失败 | `plugin_schema_history` 缺失或版本冲突 | 确认 `06-plugin.sql` 已执行；核对插件清单版本 |
